# TypeBrush — IndexedDB Database Schema (TypeBrushDB)

This document describes the design and index configuration of the client-side IndexedDB database (`TypeBrushDB`) implemented for TypeBrush.

---

## 1. Database Properties

- **Database Name**: `TypeBrushDB`
- **Current Version**: `1`
- **Driver**: Promise-based Native Web IDB API (`indexedDbService.js`)

---

## 2. Object Stores Configuration

The database registers the following object stores, each featuring a unique key configuration and performance indexes:

### 2.1. `typing_results`
Stores detailed performance logs for timed typing tests and character-level statistics.
- **Key Path**: `"id"` (string UUID/timestamp)
- **Indexes**:
  - `timestamp`: (Integer, unique: false) — Sorted queries for history logs.
  - `wpm`: (Integer, unique: false) — WPM sorting.
  - `accuracy`: (Float, unique: false) — Accuracy checks.

#### Data Schema Example:
```json
{
  "id": "rec-1723500000000-abcd",
  "timestamp": 1723500000000,
  "testType": "1-minute",
  "wpm": 65,
  "accuracy": 98.4,
  "duration": 60,
  "errors": 2,
  "correctChars": 320,
  "totalChars": 322,
  "keyStats": {
    "r": { "attempts": 24, "errors": 1, "correct": 23 },
    "e": { "attempts": 45, "errors": 0, "correct": 45 }
  },
  "mistakePairs": {
    "rt": 1,
    "ui": 1
  }
}
```

### 2.2. `gym_sessions`
Stores completed Typing Gym practice drills.
- **Key Path**: `"id"` (string UUID)
- **Indexes**:
  - `timestamp`: (Integer, unique: false) — Sorting sessions.
  - `trainingType`: (String, unique: false) — Filter drills by program.

#### Data Schema Example:
```json
{
  "id": "prac-1723500005000-xyz",
  "timestamp": 1723500005000,
  "trainingType": "weak-key-recovery",
  "target": "R",
  "difficulty": "medium",
  "duration": 60,
  "wpm": 54,
  "accuracy": 96.2,
  "errors": 3
}
```

### 2.3. `progress_tracking`
Stores level unlock milestones for curriculum programs.
- **Key Path**: `"programId"` (string unique identifier)
- **Indexes**: None (KeyPath queries only)

#### Data Schema Example:
```json
{
  "programId": "finger-placement",
  "level": 3
}
```

### 2.4. `weak_key_analysis`
Aggregated character-level statistics to feed the recovery recommendation loop.
- **Key Path**: `"id"` (String or Auto-increment)

### 2.5. `scorecards`
Stores metadata and configurations of official generated scorecards.
- **Key Path**: `"id"`

### 2.6. `achievements`
Unlocks and dates of badges completed.
- **Key Path**: `"id"`

### 2.7. `future_ai_cache`
Offline cache storing diagnostics generated by local WebLLM or remote APIs.
- **Key Path**: `"id"`

### 2.8. `future_sync_queue`
Sync actions queue (INSERT, UPDATE, DELETE) to replicate to cloud storage upon connection recovery.
- **Key Path**: `"id"`

---

## 3. Schema Scaling & Migrations

For future database changes:
- Increment version number: `version: 2` (triggers `onupgradeneeded` in `indexedDbService.js`).
- Database upgrades run atomically without erasing existing object stores.
